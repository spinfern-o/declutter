HOW TO USE THIS FILE

1. In Terminal on the Mac, get the branch that holds the work:

     cd /path/to/declutter
     git fetch origin claude/relaxed-cori-99sm8y
     git checkout claude/relaxed-cori-99sm8y

2. Find a simulator ID (you will be asked for it):

     xcrun simctl list devices available | grep iPhone

3. In a second Terminal window, start the local server and leave it running:

     cd /path/to/declutter/backend && ../.venv/bin/uvicorn server.app:app --port 8000

4. Start Claude Code in the repo folder:

     claude

5. Paste everything below the line into it. It starts with /plan, so Claude plans first and waits for
   your approval before changing anything.

POTENTIAL FEATURES (ideas to choose from, none of them built or promised)

Each of these comes from something already in the repo: a non-goal in a spec, a `// shortcut:` comment in the
code, or a gap found while building. They are grouped by what they improve.

Finding items
- Fine-tune YOLOE on my labeled photos. The model is used as it comes today, from text prompts alone. Training
  it on the Roboflow export is the likely fix if it scores below my trained model, and the only real fix for
  `shelf`, which my labels define as the open space of one level.
- Run detection on the phone with Core ML and drop the Fly.io server. Parked, with notes at the end of
  docs/handoff/2026-11-15-mac-handoff.txt. It makes the app work offline and removes the wait while the
  server wakes up.
- Let the user fix a wrong detection on the photo: tap an item to rename it, change its zone, or delete it,
  and tap empty space to add one the model missed.

The 3D cabinet
- Show the "before": blocks first where the items sat in the photo, then move to their planned shelves. Each
  item's photo position is already saved in Item.box.
- Add a shelf board by hand in 3D for cabinets where no shelves were detected, instead of the list of names.
- Let an item stay exactly where it is dropped on a shelf. Today the app lines each shelf up on its own.
- Mark items used every day so they get the easiest shelf. The organizer uses item count as a stand-in today
  (see the shortcut comment in Logic/Organizer.swift).

The room and the marketplace
- Drag one item from a cabinet straight into another cabinet or a piece of furniture in the 3D room. Today
  that goes through the list in the spot sheet.
- Stop furniture and cabinets from overlapping, and snap a piece flat against a wall when it is dragged near
  one. Today a piece is only kept inside the room's outline.
- Keep pieces inside L-shaped rooms correctly. The clamp uses the outline's bounding box (see the shortcut
  comment in Logic/RoomGeometry.swift), so an L-shaped room allows its missing corner.
- Turn and remove photographed cabinets too. Only marketplace pieces have those actions.
- A shopping list for the room: every piece added, each store's link, and the total price.
- More of the catalog, with filters by store, kind and price, and a "fits in this gap" check against the
  free floor. Every entry still has to come from one real store listing.
- Real furniture shapes in 3D for the pieces whose stores publish a model. Today every piece is a box of its
  real size.
- Place a piece in the real room through the camera to see it at full size before buying. The app already
  uses ARKit for outlining the room.

Dorms and rooms
- A dorm list with real layouts, not only floor sizes: where the door, window and closet are, and the
  furniture the school already provides (bed, desk, dresser), placed in the room when it is made.
- A source for dorm sizes that does not depend on me typing them in, such as a school's published floor
  plans. Sizes still have to be confirmed before they go in.
- Save more than one arrangement of a room and switch between them, to compare layouts.
- Share a room with a roommate so both can arrange it. This needs accounts and a database, which the app
  does not have: the server keeps nothing today.
- Scan the room with LiDAR on phones that have it, instead of tapping corners.
